# Release 0.2: numeric array and dtype foundation

**Status: planned; no 0.2 implementation or release gate has passed.** This is the execution plan for the [0.2 roadmap row](CONVERSION_ROADMAP.md), not a compatibility claim. The published [0.1 preview](RELEASE_0_1.md) is the starting point. Keep the NumPy 2.5.3 oracle, source commit `dd88c0c19b54ad9ed3533224221285bf0873249a`, and locked test environment until an explicit reference update is reviewed.

## Release boundary

The outcome is a coherent numeric `ndarray` foundation that later ufuncs can use. The supported entry points and their exact signatures must be recorded in `compat/raptors-0.2.json` as they are implemented. The release includes the existing `array`, `zeros`, and `empty` calls and the numeric array behaviors below; it does not claim every method on NumPy's scalar or `ndarray` classes.

| Area | Required 0.2 behavior | Review boundary |
| --- | --- | --- |
| Dtypes | `bool`; signed and unsigned 8/16/32/64-bit integers; `float16`, `float32`, `float64`; `complex64`, `complex128`; the platform aliases (`intp`, `uintp`, `int_`, `uint`, etc.) and available `longdouble`/`clongdouble` variants of the pinned reference. | Record canonical dtype, alias identity, item size, alignment, byte order, and the actual extended-precision representation on each supported platform. Do not silently map an unsupported extended type to `float64`. |
| Construction and dtype selection | Explicit dtype and inference from Python numeric scalars, rectangular list/tuple nesting, Raptors scalars, and Raptors arrays; zero-dimensional and empty inputs; `zeros`/`empty` defaults; requested copy/order behavior on supported inputs. | Python object/string/structured/datetime inputs, foreign buffers, and array conversion protocols belong to later releases. Invalid or unsupported inputs raise a documented error; they cannot invoke NumPy at runtime. |
| Conversion and promotion | Numeric scalar conversion, `astype`-style casts, assignment casts, safe/same-kind/unsafe rules where exposed, and promotion decisions needed for scalar interactions and later ufuncs. | Capture NumPy 2.5.3 decisions for Python scalar versus array scalar, signed/unsigned mixtures, complex/real mixtures, overflow, warnings, and invalid casts. A table of rules without executable reference cases is insufficient. |
| Layout and metadata | Checked shape, signed byte strides, offset, item size, byte order, alignment, size, flags/writeability where exposed; transpose/axis permutations, reshape, and copy/view outcomes. | `reshape` must preserve values and NumPy's observable sharing/copy behavior for contiguous, transposed, reversed, broadcast-like, scalar, and zero-size layouts. Safe access must work for non-native byte order and unaligned data or reject a construction path before any typed access. |
| Indexing and mutation | Integer, slice, tuple, ellipsis, `None`/new axis, boolean masks, integer-array/fancy indices, mixed basic/advanced indices, scalar and array assignment, broadcastable assignment, and independent copy. | Match result shape, axis placement, scalar-versus-array return, view-versus-copy behavior, index order, duplicate-index writes, aliasing, and errors. Assignment from an overlapping source must read the values NumPy would observe. |

The built-in numeric-width commitment includes platform-dependent extended precision where NumPy exposes it on the supported wheel matrix. If a target cannot represent or safely access one of these dtypes, 0.2 remains pending. Any proposed scope change needs an explicit roadmap and manifest revision; a partial dtype set cannot pass this gate as written.

Arithmetic ufuncs, reductions, and their `out=` execution belong to 0.3–0.4. Scientific routines, foreign-memory and NumPy interoperability, object and structured dtypes, the NumPy C ABI, and full scalar-class protocol compatibility remain later work. Internal promotion and broadcasting machinery may be built in 0.2, but a later public operation is not supported merely because that machinery exists.

## Current starting point and dependency order

The 0.1 path uses five typed, initialized `Vec` variants behind `Arc<RwLock<_>>` in [`raptors-storage`](../raptors-storage/src/lib.rs). Views carry checked shape, signed byte strides, and an offset. The Python binding in [`preview.rs`](../raptors-python/src/preview.rs) requires an explicit dtype for `array`, has basic integer/slice indexing, and accepts only scalar or exact-shape same-dtype assignment. The [48-case preview suite](../raptors-python/tests/preview/) is a regression gate, not evidence for the broader 0.2 contract. The legacy core is audit material only.

Implement in this order, with a separately reviewable change and evidence for each step:

1. **Audit the 0.2 inventory and author the contract.** The generated [NumPy inventory](../compat/numpy-api-2.5.3.json) currently assigns 4,449 names and members to 0.2, including scalar methods and `ndarray` routines scheduled later. Review the public entry points against the boundary above, correct the generator's phase classifications rather than hand-editing generated JSON, and record each 0.2 entry's semantic cases, status, and known limits in a versioned manifest. Preserve the full later-release backlog.
2. **Settle the storage representation.** Define one checked layout validator and access path for every numeric dtype. Decide how native and non-native byte order, alignment, and platform-specific extended values are stored before adding conversions. Keep `empty()` safe to read at the Rust boundary even though its Python values are unspecified. All allocation-size, stride, offset, and reachable-byte calculations must be checked before access.
3. **Complete dtype semantics.** Add dtype descriptors, aliases, inference, conversion, cast policy, and promotion as independently testable behavior. Preserve integer values without a floating intermediate and preserve the real and imaginary components of complex values. Resolve platform-specific `longdouble` behavior with per-wheel oracle probes before considering this step complete.
4. **Complete view and shape transforms.** Add transpose, reshape, axis handling, and metadata/flags. Prove when a result shares storage and when NumPy requires a copy; test writes through every promised view after the original Python owner is destroyed.
5. **Complete indexing and assignment.** Add new-axis/ellipsis normalization, boolean and integer advanced indexing, mixed indices, broadcasted/casted assignment, and duplicate-index behavior. Separate index planning from storage access so all index bounds and result shapes are validated before mutation. Preserve NumPy's observed partial-mutation behavior where the reference permits it; do not assume every failure is atomic.
6. **Close the release evidence.** Extend the differential and generated suites, run safety checks and the current eight-target `cp312-abi3` build-only workflow, publish a 0.2 manifest and limits, and record baseline Python-call latency, allocations, and native peak memory for representative foundation operations. Tag or publish only after every required gate passes.

## Required reference and adversarial cases

For each public behavior, save the exact NumPy call, input, expected value and dtype, scalar/array result type, shape/strides/flags where relevant, sharing and mutation result, and exception or warning category. Preserve the case's upstream source path/test ID if adapted from the pinned checkout. Compare exact integer and boolean values, bit-sensitive floating behavior where observable (including signed zero), and operation-specific complex component behavior. Do not compare `empty()`'s unspecified contents.

| Case family | Minimum examples to include |
| --- | --- |
| Dtype and conversion | Each declared dtype and alias on each supported platform; `2**53 + 1`, signed/unsigned limits, overflow and invalid casts, float16 rounding, NaN/infinity/signed zero, complex real/imaginary values, endian-swapped data, and unsupported inputs. |
| Shape and layout | Scalars, `(0,)`, `(2, 0, 3)`, contiguous C/F order, reversed and stepped slices, transposes, nested views, reshape with and without copying, invalid axes and shapes, and byte-offset/stride arithmetic near limits. |
| Ownership and aliasing | Delete each parent in a chain of views, then read and write a descendant; check independent copies; overlapping source/destination with positive and negative strides; repeated aliases and simultaneous readers/writers. |
| Indexing | Negative/out-of-range integer indices, empty/full masks, repeated and negative fancy indices, mixed basic/advanced indices, ellipsis/new axis, zero-sized axes, and wrong-rank or wrong-shape masks. Check output axis order and copy/view behavior. |
| Assignment | Scalar, casted array, broadcastable values, non-contiguous destinations, overlapping sources, repeated fancy indices, invalid shapes/casts/indices, and errors after partial work where NumPy exposes that behavior. |

Add deterministic generated operation sequences combining construction, views, indexing, writes, copies, casts, and owner deletion. Shrink failures into permanent regressions. Seed wrong dtype, result shape, byte order, axis order, aliasing, and write behavior into the harness to confirm it detects each fault. Required cases fail on import errors and have no skips or expected failures.

## Safety and release gate

- The 0.1 regression suite and every authored 0.2 differential case pass against NumPy 2.5.3 on all declared CPython and wheel targets, with zero required skips. The manifest lists only tested behavior as supported and retains unsupported inventory entries visibly.
- Rust tests exercise every layout constructor and access path, including empty allocations, negative/zero strides, non-native endian storage, misalignment decisions, shape overflow, invalid indices, and operation sequences. Miri and supported AddressSanitizer jobs pass. Any new `unsafe` block has documented preconditions and a separate review; safe Rust callers cannot cause an out-of-bounds, uninitialized, or misaligned typed read/write.
- Python-level lifetime and alias tests run against the built extension on each release wheel. Shared access guards cover all aliases; overlapping mutation neither deadlocks nor observes an invalid transient state under the declared GIL-enabled execution model.
- The build-only release workflow passes on the candidate revision for eight `cp312-abi3` targets, each tested on CPython 3.12, 3.13, and 3.14. Each wheel passes metadata and clean installation/import without NumPy. Package version, manifest, and tag contract agree before publication.
- The evidence record includes environment, exact commands, raw pass/skip/failure results, remaining limits, and baseline performance/memory measurements. A green test count alone does not establish complete NumPy compatibility or a speed advantage.

**Known blockers to resolve during 0.2:** byte order and alignment cannot be represented by the current five typed-vector variants alone; platform-specific extended precision needs a verified representation and conversion path; the generated inventory's 0.2 assignments overstate this release's public method scope; and the existing test/CI default only runs the 0.1 preview suite. These are planned work, not passed gates.
