# Release 0.3: numeric ufunc release candidate

**Status:** release candidate for `0.3.0`. At revision `daf0318f7eb475d70ebdd64598e76f9fa2e67f17`, the Darwin arm64 preview suite passes (9,457 passed, 6 platform-conditional skips) and the differential suite passes (8,683 passed, zero required skips). The six suite skips are one Windows-only typecode case and five native extended `long double` cases; the hosted matrix exercises those behaviors on their applicable targets. Hosted CI and the build-only release workflow passed on this revision, including the eight-target wheel matrix tested on CPython 3.12–3.14. The release tag has not been created and no 0.3.0 package has been published. The oracle remains NumPy 2.5.3 at source commit `dd88c0c19b54ad9ed3533221285bf0873249a`.

## Release boundary

The frozen namespace is the **101 top-level elementwise ufunc names** assigned to 0.3 in [`compat/numpy-api-2.5.3.json`](../compat/numpy-api-2.5.3.json), including aliases. The reviewed [`compat/raptors-0.3.json`](../compat/raptors-0.3.json) records their pinned names, signatures, numeric loops, known limits, and release evidence. The generated contract and Rust loop tables can be refreshed with [`scripts/generate_ufunc_metadata.py`](../scripts/generate_ufunc_metadata.py); any scope change requires updating the reviewed contract and rerunning the release gate.

| Area | Required 0.3 behavior | Boundary |
| --- | --- | --- |
| Elementwise calls | Numeric arithmetic, bitwise/logical, comparisons, predicates, transcendental functions, rounding, and multi-output functions in the 101-name set. Public aliases resolve to the same ufunc object where NumPy does. | Use the 0.2 numeric dtype set (`b`, `i`, `u`, `f`, `c`), including platform-dependent extended forms. For each operation, support exactly the input dtype combinations and output dtypes offered by the pinned oracle on that platform; a dtype in the foundation is not automatically valid for every ufunc. |
| Ufunc objects | Callable objects with reviewed `nin`, `nout`, `nargs`, `ntypes`, `types`, `identity`, `signature`, `__name__`, and applicable public methods. Calls return the reference-compatible array or scalar form, including multi-output tuples. | Arbitrary construction of new ufuncs and user-defined dtype loops remain outside this numeric execution slice unless required by a reviewed 0.3 entry. |
| Call controls | Positional and keyword `out`, `where`, `dtype`, `casting`, `order`, `subok`, and `signature`/`sig` behavior where the pinned ufunc accepts them. Invalid keyword, cast, shape, output count, and writeability cases must match the oracle. | Subclass and third-party dispatch protocols are reserved for 0.8; for 0.3, document behavior for Raptors arrays, Raptors numeric scalars, and Python numeric scalars only. |
| Methods | `reduce`, `accumulate`, `reduceat`, `outer`, and `at` on each promised ufunc. Match valid results and reference-compatible errors for methods that do not apply to a particular ufunc. | `ndarray.sum`, `np.sum`, `mean`, and other separate array routines remain in 0.4 even when a related ufunc method works. |
| Operators | Numeric ndarray and supported scalar arithmetic/comparison operators, including reflected and in-place forms, routed through the same promotion, broadcast, and kernel rules. | Matrix multiplication operators and generalized ufuncs `matmul`, `matvec`, `vecdot`, and `vecmat` are 0.5 work. Full NumPy scalar class/protocol identity remains later work. |
| Floating errors | Default warnings and errors plus `geterr`, `seterr`, `errstate`, `geterrcall`, and `seterrcall` for supported numeric ufuncs. | State and callback behavior must be checked on each supported Python/runtime target before the release gate. |

`numpy.matlib` is a later public-submodule obligation, not evidence of 0.3 ufunc support. Datetime/timedelta, object, string, structured, user-defined dtype, foreign-buffer, NumPy C ABI, and free-threaded Python behavior remain outside this release. There is no implicit NumPy runtime fallback.

## Implementation snapshot

The numeric loop matrix is generated from NumPy 2.5.3 `resolve_dtypes` and the numeric subset of each object's `types` list. The Rust binding routes ordinary calls, `outer`, and the scalar kernels through that table. `reduce`, `accumulate`, `reduceat`, and `at` are wired for applicable one-output ufuncs; `at` uses write-through advanced-index offsets so repeated and broadcasted index arrays update sequentially. `outer` handles one- and two-output binary ufuncs. Operators use the same call path. `errstate` uses context-local state and callback overrides, including when an async context manager spans `await`; decorator use is supported for synchronous functions. It is available alongside `geterr`, `seterr`, `geterrcall`, and `seterrcall`. Error-policy tests cover all four flag categories under all six modes, combined callback flags, task isolation, and precedence among conflicting call controls and invalid outputs.

The local 0.3 benchmark is recorded in [`docs/benchmarks/raptors-0.3-baseline.json`](benchmarks/raptors-0.3-baseline.json) with 20 correctness-checked observations for the NumPy and Raptors Python APIs. It records median latency, Python traced-memory bytes, net live-block snapshots, and coarse process peak RSS. Wider-than-binary64 real and complex scalar kernels use the isolated native bridge on targets where C `long double` is wider than binary64; the hosted wheel matrix qualified these native ABI paths and the binary64 aliases. Complex inverse-trig tests cover signed branch cuts at all complex precisions, small imaginary components, and large finite values; mixed binary input loops are differentially checked across every valid numeric dtype pair. Advanced-index `at` updates use write-through offsets and preserve sequential behavior for repeated indices.

## Completed implementation sequence

1. **The oracle matrix was frozen.** The 101 names and aliases were checked against the pinned wheel and source. The contract records arity, loop signatures, method applicability, scalar returns, keyword support, warnings, errors, and deferred protocols.
2. **A checked execution plan was built.** Input resolution, dtype promotion and loop selection, broadcasting, outputs, casting, masks, and alias relationships are preflighted before writes. Scalar kernels use the 0.2 storage and checked signed-stride views.
3. **The complete add path was proved.** Tests cover arrays and Python/Raptors scalars, mixed dtypes, broadcasting, reverse/transposed views, `out`, `where`, in-place/reflected operators, and `add.reduce` controls.
4. **The semantic families were expanded.** Arithmetic, comparisons, bitwise/logical operations, predicates, rounding, transcendental and complex behavior, multi-output operations, and aliases are covered by the pinned reference cases.
5. **The method and state layer was completed.** Applicable ufunc methods, output alias handling, floating error policies, and operator entry points preserve sequential `at` behavior and method-specific validation.
6. **The release gate was recorded and run.** The contract captures passing local and hosted evidence. Its status remains a release candidate until the validated version is tagged and published.

## Differential cases and safety evidence

For every promised ufunc or alias, author cases for its signature and defaults, valid dtype loops and rejected casts, output shape/dtype/type, representative values, boundaries, and errors/warnings. Use exact comparison for integer/boolean results and operation-specific floating criteria; record signed zero, NaN/infinity, overflow, underflow, domain, and complex branch behavior deliberately. Test C/F, transposed, reverse-strided, zero-stride broadcast, zero-dimensional, and zero-size inputs. Include Python scalar promotion, large integers without floating conversion, non-native byte order, and platform-dependent long-double forms.

For `out` and `where`, test one or multiple outputs as appropriate, mask broadcasting, all-false masks, destination preservation where false, invalid output shape/dtype, in-place calls, partially overlapping inputs/outputs, and parent deletion while views remain alive. Fresh output values at masked-off positions are unspecified unless NumPy specifies them; test preservation only when an output was supplied. For methods, include negative and tuple axes where valid, duplicate `at` indices, empty reductions and identity/`initial` behavior, `reduceat` index boundaries, `accumulate` result dtype, and mutation/error ordering.

The harness must fail on injected wrong dtype promotion, broadcast shape, mask handling, reduction axis/identity, alias snapshots, warning category, and owner-lifetime results. Required cases have zero skips or expected failures. A missing extension, an imported NumPy runtime dependency, or a hidden fallback fails the gate. Record provenance for adapted upstream tests and keep minimized generated failures as regressions.

Review any new unsafe code and concurrency/alias rules. Run Rust storage and execution tests normally and under Miri, supported sanitizer jobs, and operation-sequence property/fuzz cases involving views, writes, `out`, and owner destruction. A new execution path must not form out-of-bounds, uninitialized, or misaligned typed reads/writes through safe APIs. Preserve 0.2 foundation cases and the NumPy-free clean-install check.

## Release gate and evidence bundle

- `compat/raptors-0.3.json` names the exact API, dtype-loop and keyword boundary, known limits, reference version, test files, and unsupported behavior. Inventory entries are reconciled against it; a generated assignment alone cannot mark an API complete.
- The differential suite passes every promised signature, result, dtype, error, warning, and mutation case on CPython 3.12–3.14 for each supported wheel target, with no required skips and NumPy fallback disabled. The same wheels pass clean install and representative numeric calls without NumPy installed.
- Rust checks, Miri, supported sanitizers, reviewed unsafe/alias invariants, wheel metadata, and the eight-target stable-ABI matrix pass. Findings are resolved or remove the relevant operation from the promised contract before a release candidate is tagged.
- A reproducible 0.3 Python baseline records full-call latency, allocation count, native peak memory, and conversion cost for tiny/medium/large inputs, contiguous/strided/broadcast layouts, mixed dtypes, fresh and reused outputs, and reductions. Correctness is checked before timing. No speed threshold applies in 0.3.
- The release record links the manifest, exact test/CI runs, benchmark JSON, wheel artifacts, and known limits. README published-release stats change only after publication. The 0.4 optimization targets remain separate.
